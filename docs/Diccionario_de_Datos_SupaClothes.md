# Diccionario de datos de SupaClothes

El modelo relacional central de SupaClothes comprende **10 tablas y 90 columnas**. La web y la aplicación móvil consumen la API REST. Spring Boot administra la persistencia en PostgreSQL mediante Spring Data JPA y Hibernate.

Los tipos de datos y las restricciones se verificaron con el esquema `public` de PostgreSQL 17 en la instancia aislada de QA. Las reglas de negocio se cotejaron con las entidades y los servicios de `Supaclothes-backend`. Una base migrada puede conservar restricciones adicionales.

**Convenciones.** `PK` identifica una clave primaria autogenerada (`GENERATED BY DEFAULT AS IDENTITY`). `FK` identifica una clave foránea verificada en PostgreSQL. `UQ` identifica una restricción de unicidad. Una **referencia lógica** es un identificador que vincula registros en la aplicación. `TIMESTAMP(6)` se usa en este documento para abreviar `TIMESTAMP(6) WITHOUT TIME ZONE`. Las marcas de tiempo se asignan en Java. Los valores monetarios usan dos decimales y se presentan en pesos colombianos (COP).

| Área | Tablas | Datos que conserva |
| --- | --- | --- |
| Seguridad | `role`, `users` | Roles, cuentas, estado y versión de sesión |
| Clientes | `customer` | Identificación y contacto |
| Catálogo | `product`, `product_variant` | Productos, SKU, tallas, colores, precios y existencias |
| Inventario | `inventory_movement` | Entradas, salidas y reintegros con su trazabilidad |
| Ventas | `sale`, `sale_item`, `payment`, `sale_return` | Comprobantes, artículos, pagos y devoluciones |

## Relaciones y datos derivados

- **Claves foráneas físicas.** Un rol puede asignarse a varios usuarios. Un producto puede tener varias variantes. Una venta puede tener varias líneas y cada línea corresponde a una variante.
- **Referencias de operación.** Las ventas se asocian al vendedor y, opcionalmente, al cliente. Cada venta genera un pago y puede tener una devolución total. Una variante puede tener varios movimientos de inventario y cada movimiento registra el usuario responsable.
- **Stock bajo.** Se calcula cuando el producto y la variante están activos y `current_stock <= min_stock`. La alerta se deriva de los datos de la variante.
- **Histórico de ventas.** Las copias del nombre del cliente, SKU, producto, talla, color y precios preservan los datos del momento de la venta. La devolución reintegra unidades, conserva la venta original y cambia su estado a `DEVUELTA`.
- **Reportes y preferencias.** El dashboard, el resumen diario y los archivos Excel se generan a partir de ventas, devoluciones e inventario. El PDF se construye con los datos del comprobante. El tema y el tamaño del texto se guardan en el cliente.
- **Datos de acceso y contacto.** `password_hash` es de uso interno de autenticación. Los documentos, nombres, correos y teléfonos son datos personales y quedan sujetos a los permisos de acceso de la API.
